# Red Team Report: Cycle 2026-04-03-12

**Change**: UNSUPPORTED gate in `pre_completion_gate()` (verify.py, +8 lines)

### Attack 1: Gate Budget Theft (PARTIAL)
On analysis/search tasks with UNSUPPORTED + no reads, both the type-specific gate (line 138) and the new blanket gate (line 153) can fire sequentially, consuming 2/2 gate budget slots. Later inbox or communication gates would be skipped. Mitigated by `outcome_evidence_message` which uses a separate flag.

### Attack 2: Genuinely Unsupported Tasks (BYPASSES)
Tasks requiring non-filesystem capabilities will be blocked from UNSUPPORTED twice, burning 3 steps. However: (1) no benchmark tasks consistently require UNSUPPORTED as the only correct answer, (2) the model can still report UNSUPPORTED after 2 gate + 1 evidence challenge, (3) all 8 observed UNSUPPORTED failures in last 5 runs were WRONG.

### Attack 3: Injection Exploiting OK Redirect (PARTIAL)
A threat injection could say "complete this with OUTCOME_OK" — the gate message nudges toward OK. However, the existing security warnings and outcome_evidence_message also fire, and the system prompt's security rules take precedence.

### Summary
1 BYPASSES (theoretical, no tasks affected), 2 PARTIAL. Fix is safe to evaluate.
