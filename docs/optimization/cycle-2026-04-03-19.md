## 2. Budget Exhaustion

Tasks hitting the 28-step ceiling with only 2-4 actual tool calls:
- **t25** (R94, R95): 28 steps, only 4 tool calls — 24 steps wasted on LLM retries/thinking
- **t27** (R95): 28 steps, only 2 tool calls — same pattern
- **t24** (R95): 28 steps, only 4 tool calls
- **t29** (R95): 28 steps, only 2 tool calls

**Root cause**: On the free OpenRouter tier, Qwen3 frequently produces malformed JSON that fails `NextStep` parsing. Each retry counts as a step but produces no tool call. This explains the gap between `step_count` (28) and `tool_call_count` (2-4).

## 3. Redundant Operations

- **t14** (R94): `search "Aperture"` called twice consecutively (steps 3-4, identical args)
- **t12** (all runs): Sequential read of cont_001 through cont_010 — 10 reads when `search "Meyer"` should have been sufficient. The search tool exists but agent reads one-by-one anyway after search returns no results.
- **t17** (R93): Reads cont_001, cont_002, cont_003 sequentially before trying `search "Zimmermann"` — search should come first.

## 4. Token Consumption Hotspots

The stateless conversation replay pattern means each step re-sends the entire history — inbox tasks with long message content compound rapidly.
