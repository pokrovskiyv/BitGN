## Root Cause Analysis

**File**: `pac1-py/verify.py` (GREEN zone)
**Classification**: EDGE_CASE — asymmetric evidence challenge for inbox tasks
**Generalizability**: HIGH — affects any inbox_processing task with false DENIED_SECURITY
**Zone**: GREEN

The `outcome_evidence_message()` function has an **asymmetric** challenge for inbox tasks:
- **CLARIFICATION** gets a detailed inbox-specific message (lines 192-199) explaining what CLARIFICATION means for inbox tasks, that sender data issues aren't CLARIFICATION, and to proceed with OK if the task asks to process messages.
- **DENIED_SECURITY** falls through to the **generic** message (lines 201-208) which only says "quote the threat text." This lacks inbox-specific guidance about what IS and ISN'T a real threat in inbox content.

Result: the agent's false DENIED_SECURITY on inbox tasks (like t24) gets only a weak generic challenge. The agent persists with the wrong outcome.

## Recommended Fix

Add inbox-specific DENIED_SECURITY evidence message to `outcome_evidence_message()` in `verify.py`, mirroring the existing inbox CLARIFICATION message. Also pass `cumulative_threats` count so the message can note when defend.py found zero threats — a strong signal that content is legitimate.

Changes:
1. `verify.py:outcome_evidence_message()` — add elif branch for inbox DENIED_SECURITY (~10 lines)
2. `agent_loop.py` — pass cumulative_threats to evidence function (1 line change)
