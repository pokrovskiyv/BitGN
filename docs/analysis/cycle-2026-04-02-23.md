## Root Cause Analysis

All four tasks have instruction "process inbox". `classify_task()` correctly identifies them as `inbox_processing` (classify.py:131-139). However, `strategy.py:_STRATEGY_TABLE` has **no `inbox_processing` entry**.

Result: `decide_strategy()` raises `KeyError: 'inbox_processing'` at strategy.py:79 before the agent loop starts. The agent never processes these tasks.

**Confirmed via direct test:**
```
>>> classify_task("process inbox", []).task_type
'inbox_processing'
>>> decide_strategy(classify_task("process inbox", []))
KeyError: 'inbox_processing'
```

The `addons` dict in `decide_strategy()` also lacks the `inbox_processing` key, so the `inbox_processing.md` prompt fragment (79 lines, fully written) is never loaded.

**Root Cause Classification**: TOOL_ERROR (infrastructure gap — missing strategy table entry)
**Generalizability**: HIGH — affects 100% of inbox tasks (4 tasks, 4 points)
**Zone**: GREEN (strategy.py — infrastructure code)

## Recommended Fix

Add 2 entries to `strategy.py`:
1. `_STRATEGY_TABLE["inbox_processing"] = (28, "hardened", True)` — matches CLAUDE.md spec
2. `addons["inbox_processing"] = _load("prompts/fragments/inbox_processing.md")`

This is a 2-line change. The prompt fragment already exists and is well-tested in verify.py's gate logic. Deterministic code fix — immune to model variance.
