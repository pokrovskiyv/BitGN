## Target: Premature completion on complex task types

### Failure Pattern (R84-R88+R91, short-step failures)

Step trace from run_history.json shows 3-step completions on complex tasks:

| Task | Steps | Tools | Expected | Failure |
|------|-------|-------|----------|---------|
| t15  | 3     | search, tree, report | UNSUPPORTED/CLARIFICATION | OK (premature) |
| t29  | 3     | read, read, report | SECURITY | OK (premature) |
| t30  | 3     | read, search, report | OK | CLARIFICATION (premature) |
| t25  | 4     | read, read, read, report | SECURITY | OK/CLARIFICATION |
| t12  | 5     | read, search×3, report | CLARIFICATION | UNSUPPORTED |

These tasks complete with 0-3 tool calls before reporting. For communication, analysis, inbox_processing, and multi_step tasks, this is insufficient exploration — the agent barely reads the filesystem before deciding an outcome.

### Root Cause
**Classification**: PROTOCOL — existing premature completion gate is too lenient
**File**: `pac1-py/verify.py` line 118 (GREEN zone)
**Generalizability**: HIGH — affects ALL complex task types that complete prematurely

Current gate: `if outcome == "OUTCOME_OK" and step < 2` — only blocks OK at 0-1 tool calls.

Complex tasks need minimum exploration (list dirs, read files, verify context) before ANY outcome is valid. A 3-step completion on a communication or analysis task means the agent didn't gather enough data to make a correct outcome decision.

### Why this is NOT a prompt fix
- The outcomes.md already describes when to use each outcome
- The model already gets VERIFY messages for non-OK outcomes
- The problem is timing: the model decides too early, before it has enough evidence
- This fix forces more exploration via code, not persuasion

### Recommended Fix
Add per-task-type minimum step thresholds to `pre_completion_gate()`:

```python
_MIN_STEPS = {"communication": 4, "analysis": 4, "inbox_processing": 4, "multi_step": 4}
min_step = _MIN_STEPS.get(task_type, 0)
if min_step and step < min_step:
    return (
        f"HOLD: Only {step + 1} tool calls completed for a {task_type} task. "
        "Explore more — list directories, read key files, verify your understanding "
        "before reporting any outcome."
    )
```

- ~5 lines added to verify.py
- No changes to agent_loop.py (step parameter already passed)
- Existing completion_gate_count (max 2) caps the gate
- Simple crud/search/security_test tasks unaffected (no minimum)

### Safety
- Gate fires at most 2 times (shared completion_gate_count budget)
- Agent can still complete after doing more exploration
- No risk for simple tasks (crud min=0, security_test min=0)
- Budget overhead: max 2 extra steps consumed, but complex tasks have 18-28 step budgets
- If the agent's original outcome was correct, it can re-affirm after exploring more
