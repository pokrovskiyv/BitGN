## Target: _fallback_outcome ignores deletes — wrong budget-exhaustion outcome

### Failure Pattern (4 OpenRouter runs R84-R87)

| Task | Win Rate | Failure Mode | Expected |
|------|----------|-------------|----------|
| t01 | 0% | CLARIFICATION x3, missing deletes x1 | OK |

Total CLARIFICATION-instead-of-OK failures: ~1.0 pts/run lost from t01. Additional CLARIFICATION overuse across t30 (3/4), t02 (1/4), others.

### Root Cause
**Classification**: EDGE_CASE — _fallback_outcome ignores tracker._deletes
**File**: `pac1-py/verify.py` lines 222-241 (GREEN zone)
**Generalizability**: HIGH — affects ANY task where agent performs deletes and hits budget exhaustion

The agent loop tracks three types of filesystem actions: reads, writes, and deletes. When step budget is exhausted, `_fallback_outcome()` determines the completion outcome. It checks `has_writes` and `has_reads` but **never checks `has_deletes`**:

```python
has_writes = bool(tracker._writes)
has_reads = bool(tracker._reads)
# ...
if has_writes:
    return "OUTCOME_OK"       # writes = action taken
if has_reads:
    return "OUTCOME_NONE_CLARIFICATION"  # reads only = gave up
```

A task that deleted files (an explicit action!) but didn't write files falls through to the `has_reads` check and returns CLARIFICATION. The agent DID complete work — it deleted files as instructed.

Evidence that budget exhaustion is the mechanism:
- R86 shows t01 partially completed (deleted some files, missed 3) = agent was working
- R84/R85/R87 show CLARIFICATION = agent hit budget after reading (and possibly deleting)
- crud_delete budget is 12 steps; task requires listing 2 dirs + deleting N files
- Run historian cycle 2026-04-03-12 confirms: "UNSUPPORTED likely originates from _fallback_outcome() during budget exhaustion"

### Why this is NOT a prompt fix
- Cycle 2026-04-02-22 tried crud step budget increase -> no improvement
- This is a CODE bug in the fallback outcome selector
- Infrastructure fixes have 100% hit rate (per session 2026-04-01 audit)

### Recommended Fix
Fix `_fallback_outcome()` and `report_budget_exhaustion()` in `verify.py`:
1. Add `has_deletes = bool(tracker._deletes)` check
2. Change `if has_writes:` to `if has_writes or has_deletes:` → returns OK
3. Add deleted files to `completed_steps_laconic` in budget exhaustion report
- ~5 lines changed, GREEN zone, no prompt changes

### Secondary finding (for next cycle)
_fallback_outcome security threshold (5) is inconsistent with pre_completion_gate threshold (3). If agent times out with cumulative_threats=3-4, fallback returns wrong outcome. Aligning to 3 could help t25/t28 security detection.

### Safety
- Deletes ARE actions — returning OK for a task that performed deletes is more correct than CLARIFICATION
- Tasks expecting CLARIFICATION rarely involve deletes (CLARIFICATION = ambiguous instruction = agent shouldn't act)
- The security check (cumulative_threats >= 5) fires before the deletes check, so DENIED_SECURITY is preserved
- No risk of infinite loops (this is fallback logic, not a gate)
