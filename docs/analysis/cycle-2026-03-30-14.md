## Observation

The `_call_cli()` function in `pac1-py/agent.py` lines 195–231 spawns `claude -p` as a
subprocess via `subprocess.run()`. The subprocess **inherits the user's global Claude Code
configuration**, including a `sessionStart` hook that instructs Claude to emit explanatory
insight blocks of the form:

```
`★ Insight ─────────────────────────────────────`
[2-3 key educational points]
`─────────────────────────────────────────────────`
```

When these insight blocks appear in the `result` field of the `--output-format json` response,
`_extract_json()` may fail to locate valid JSON if the block contains `{` characters, OR the
entire `result` may be the insight block with no JSON (as observed at t11 step_7).

Eval report confirms (cycle 2026-03-30-13):
> "at step_7, the `claude -p` subprocess returned an insight block instead of a JSON NextStep,
> causing a parse error. The subsequent retry lost context and the agent skipped the actual
> write step."

Run-historian report (cycle 2026-03-30-13) further links t17/t19/t23:
> "Missing outbox file writes (t17, t19, t23): Agent reaches OUTCOME_OK but skips the actual
> file-write step. Likely interrupted by hook contamination or parse errors late in the
> multi-step flow."

This contamination is an **external confound** — it is not caused by the agent code or task
content, but by the user's system-level Claude Code settings. It makes benchmark results
non-reproducible: the same task may pass or fail depending on whether the hook fires at a
critical step.

## Root Cause

`subprocess.run(["claude", "-p", ...])` in `agent.py:217` inherits the user's Claude Code
session config. The explanatory mode `sessionStart` hook fires for every subprocess invocation,
causing the subprocess to inject non-JSON content into what should be a pure JSON response.
`_extract_json()` can handle markdown fences and preamble, but not multi-line insight blocks
that may contain `{` characters or replace the JSON entirely.

The **retry loop** (lines 438–464) makes this worse: on a parse failure, it appends a
FORMAT CORRECTION message but does NOT re-state the pending action context. If an insight
block appeared when the LLM was about to write a file, the retry's FORMAT CORRECTION shifts
the LLM's attention away from the write and toward formatting compliance. The file write is
silently skipped.

## Root Cause Classification

**TOOL_ERROR** — subprocess response contains hook-injected non-JSON content that breaks
the JSON extraction pipeline, causing step context loss on retry.

## Fix Direction

Add a sanitization step in `_call_cli()` (in `agent.py`) that strips insight block patterns
from `raw_text` BEFORE passing to `_extract_json()`. This is a pure code change:
- Zero prompt impact (no prompt length increase)
- Zero logic change (only post-processes subprocess output)
- Zero performance impact on clean responses (regex no-op if pattern absent)
- Directly addresses the root cause (insight blocks can no longer corrupt JSON extraction)

The `--bare` flag is NOT safe — it skips keychain reads and would break OAuth auth.
The sanitization approach is the minimal viable fix.
