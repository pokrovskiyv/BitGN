## Root Cause Analysis

`strategy.py` has TWO gaps for `inbox_processing`:

1. **`_STRATEGY_TABLE` missing key** (line 41-50): No `"inbox_processing"` entry → `KeyError` crash. Tasks classified as `inbox_processing` by `classify.py` never execute. The exception is caught by `_run_single_task()` in `main.py:248-249`, so the task silently scores 0.

2. **`addons` dict missing key** (line 62-69): No `"inbox_processing"` entry → `inbox_processing.md` prompt fragment (79 lines of channel/OTP/email/security guidance) is never injected. Even when the previous fix added the strategy table entry, the agent ran inbox tasks WITHOUT the specialized guidance, resulting in wrong outcomes (t23 wrote unexpected files, t25/t28 missed security threats).

The previous fix (commit 5f29b41) only addressed gap #1. The eval report explicitly states: "Fix is correct but cannot be validated under current API conditions" (41-53 empty OpenRouter responses per run).

**Root Cause Classification**: EDGE_CASE (infrastructure routing gap — task type exists but isn't wired)
**Generalizability**: HIGH — affects ALL tasks classified as `inbox_processing`
**Zone**: GREEN (strategy.py — infrastructure code, not prompt text)
