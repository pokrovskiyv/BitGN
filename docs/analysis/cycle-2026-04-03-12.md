### Root Cause
**Classification**: EDGE_CASE — missing gate for UNSUPPORTED outcome
**File**: `pac1-py/verify.py` lines 138-153 (GREEN zone)
**Generalizability**: HIGH — affects ANY task type where model incorrectly reports lack of capability

`pre_completion_gate()` checks for:
1. Premature OK (step < 2) ✓
2. Inbox without reads ✓
3. Inbox without ALL files ✓
4. Analysis/search + CLARIFICATION/UNSUPPORTED + no reads ✓
5. Communication + CLARIFICATION + no contacts ✓

**Missing**: General UNSUPPORTED gate. The agent has full filesystem tools — UNSUPPORTED is almost never correct. Gate 4 only catches analysis/search tasks with no reads. If the model reads some files but still claims UNSUPPORTED, or if it's a non-analysis task type, no gate fires.

### Why this is NOT a prompt fix
Cycle 2026-04-02-20 tried expanding the UNSUPPORTED/CLARIFICATION boundary in `outcomes.md` → REGRESSED. Prompt changes don't work reliably on free-tier models. This fix is a CODE gate — it challenges the outcome before dispatch, giving the model 2 chances to reconsider. Infrastructure fixes have 100% hit rate (per session 2026-04-01 audit).

### Recommended Fix
Add a catch-all UNSUPPORTED gate to `pre_completion_gate()` in `verify.py`:
- Place after all specific gates, before `return None`
- Message guides toward both OK (for tasks like t16) and CLARIFICATION (for tasks like t12)
- ~7 lines, GREEN zone, no prompt changes

### Safety
- Gate is capped at 2 attempts by existing `completion_gate_count` mechanism
- For genuinely unsupported tasks, model can still report UNSUPPORTED after 2 challenges + 1 evidence challenge
- No risk of infinite loops
