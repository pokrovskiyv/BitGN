## Root cause hypothesis

**Exactly one hypothesis:**

`_SEARCH_SIGNALS` in `classify.py` (line 41) hardcodes `when\s+is` as the only "when" form. Any question phrased as "When did X happen", "When was X", or "When were X" produces zero signal hits and falls through the classifier to CRUD. The `_QUESTIONISH_LOOKUP_SIGNALS` regex (line 90) does recognize the leading "when", but it only gates the questionish-bypass at line 214 (`is_questionish_lookup`) — which itself is only consulted inside the `if (has_search or has_lookup) and …` branch. Without `has_search=True` upstream, the questionish flag is dead code for "when did" / "when was" phrasings.

**Evidence chain:**
1. Regex test over the task text confirms every content signal returns `False` except `_QUESTIONISH_LOOKUP_SIGNALS` (verified via standalone `re.search` run against the live patterns — see `classify.py` lines 35–93).
2. The fall-through reaches the unconditional CRUD default at line 236 (`return TaskClassification(task_type="crud", estimated_steps=10 if not has_delete else 12, …)`).
3. `strategy.py` then loads `_STRATEGY_TABLE["crud"]` → `(15, "standard", True)` and composes the prompt with `crud.md` via `addons["crud"]` (line 83), not `search.md` — the agent never sees `LOOKUP DISCIPLINE` or `ANSWER PRECISION`.
4. The trajectory matches exactly what a CRUD-posture agent would do on a lookup task: no canonical-directory walk, empty-args tree probe, late AGENTS.md read, and an early stop because the `crud.md` rubric ("re-read after writing") is irrelevant and offers no stopping-criterion for a lookup.

This is a root cause, not a symptom: fixing any downstream artifact (tree args, stopping criterion, answer precision) without repairing classification would leave all other "When did/was …" tasks still misrouted.

## Fix proposal (narrow GREEN zone only)

**Selected fix class:** `classify_rule`

**Target file:** `pac1-py/classify.py`

**Exact change:**
```diff
 _SEARCH_SIGNALS = re.compile(
     r"\b(find|search|locate|look\s+for|where\s+is|which\s+files?|what(?:'s|\s+is)|"
-    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me)\b",
+    r"which\b|who\s+is|who\s+are|when\s+(?:is|was|did|were|does|do)|"
+    r"how\s+(?:long|old)|can\s+you\s+tell\s+me)\b",
     re.IGNORECASE,
 )
```

**Rationale:** One-character regex expansion turns `when\s+is` into an alternation covering every common "when"-interrogative form: `when is / when was / when did / when were / when does / when do`. Also adds `how long` / `how old` which are structurally identical factual lookups ("How long has X been running?", "How old is entity Y?") and share the exact same misrouting risk. The change is additive — no existing classification path is altered, only more inputs now flow into the `search` branch instead of the CRUD fall-through. Because the `search` branch at line 214 is gated by `is_questionish_lookup` for leading-question forms, this interacts cleanly with the existing `_QUESTIONISH_LOOKUP_SIGNALS` logic that already anchors on leading "when".

Why this and not a `prompt_fragment` fix: the root cause is that the wrong fragment is loaded. Patching `crud.md` to also teach lookup discipline would muddy the CRUD posture for actual write tasks and hurt `t003`-style crud jobs. Patching `search.md` cannot help here because it is never loaded. The minimal, correct intervention is at the routing layer.

Why not a `strategy_budget` fix: budget was not the failure mode (5/15 used).

**Generalizability:** `MEDIUM` (H=5+ similar, M=2-4, L=1)

Estimate: 2–4 tasks in the 104-task benchmark likely match "When did / When was / When were … ?" phrasing. The "How long / How old" additions widen this slightly. I have not scanned `task_cache.json` exhaustively for every "when did" / "when was" opening, so I cannot honestly claim HIGH. The confidence is MEDIUM because the pattern is common in natural-language benchmark questions but the absolute count in this specific dataset is in the low single digits based on the handful of search-type tasks already classified correctly via "when is".

**Zone:** `GREEN` — pure `classify_rule` change, one regex line edit in `classify.py`. No Python code paths added or removed. No impact on security posture (`_compute_threat_level` is independent). No impact on write/delete routing (`_WRITE_SIGNALS` untouched). Cannot regress inbox/communication tasks because those branches trigger before the search branch (lines 169, 181, 192 in classify.py).

**Expected impact:** +1 on t076 (assuming the correct answer is `03-04-2026` from the folder prefix `2026_04_03_black_library_evenings`, which `search.md`'s `LOOKUP DISCIPLINE` would have guided the agent to commit to cleanly). Potentially +1 to +2 on other `when did / when was` lookups elsewhere. Honest conservative estimate: **+1 to +2 tasks**.

**Risks:** Very low. The only plausible regression is that a task phrased "When did you delete file X?" would now classify as search instead of falling through; that fall-through currently lands on CRUD anyway, so the behavior shifts from "CRUD 15 steps + `crud.md`" to "search 24 steps + `search.md`" — which is strictly better for lookup-style questions. A task like "Process this when done" would not match because `_MULTI_STEP_SIGNALS` already captures `when\s+done` (line 62) and runs before the search branch.
