## Root cause hypothesis

**Exactly one hypothesis:**

`classify.py` lacks any pattern matching the phrase `how much` (monetary/quantity lookups), so financial/quantitative read-only questions fall through to `crud` instead of `search`. `_ANALYSIS_SIGNALS` at line 52 carries `how\s+many` but not `how\s+much`; `_SEARCH_SIGNALS` at line 42 carries `what(?:'s|\s+is)` but no `how` branch at all. Any task phrased as "how much did X cost / charge / pay / owe" is silently misrouted.

**Evidence chain:**
1. Running the classifier regexes against the task text manually: `_WRITE_SIGNALS` no match ("charge" is not write-like), `_DELETE_SIGNALS` no match, `_SEARCH_SIGNALS` no match (no `what is`, no `find`, no `where`), `_LOOKUP_SIGNALS` no match (no `owned by`, no `legal entity`), `_ANALYSIS_SIGNALS` no match (`how_many` not `how_much`), `_MULTI_STEP_SIGNALS` no match, `_COMMUNICATION_SIGNALS` no match, `_INBOX_PROCESSING_SIGNALS` no match. Confirmed fallthrough to `crud`.
2. Trajectory symptoms are diagnostic of missing `search.md`: four empty-pattern searches, never called `context()`, no canonical-folder-first walk, step 5's 28.5s think trying to re-arithmetic the date. All these are exactly what `search.md` exists to prevent.
3. Root, not symptom: fixing `outcomes.md` would not help — by the time the agent got to `report_completion`, it had already burned 14/15 steps and never located the right file. The fix must happen upstream at classification.

## Fix proposal (narrow GREEN zone only)

**Selected fix class:** `classify_rule`

**Target file:** `pac1-py/classify.py`

**Exact change:**
```diff
 _SEARCH_SIGNALS = re.compile(
     r"\b(find|search|locate|look\s+for|where\s+is|which\s+files?|what(?:'s|\s+is)|"
-    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me)\b",
+    r"which\b|who\s+is|who\s+are|when\s+is|how\s+much|how\s+long|how\s+old|"
+    r"can\s+you\s+tell\s+me)\b",
     re.IGNORECASE,
 )
```

**Rationale:** Adds `how much`, `how long`, `how old` to `_SEARCH_SIGNALS`. These are all read-only factual quantity/duration lookups with the same semantic shape as `what is the X`. Because the classifier runs `_SEARCH_SIGNALS` check before the `crud` fallthrough at line 214 (`if (has_search or has_lookup) and (not has_write or is_questionish_lookup)`), a `how much … charge me` task now correctly routes to `search`, loads `search.md`, gets the 24-step budget, and inherits LOOKUP DISCIPLINE + DATE LOOKUPS guidance.

The `is_questionish_lookup` guard at the same line is also relevant: `_QUESTIONISH_LOOKUP_SIGNALS` at line 90 already anchors on `^\s*(?:what(?:'s|\s+is)|which|who|where|when|can\s+you\s+tell\s+me)`. To match the prompt policy consistently, the same `how much|how long|how old` terms should be appended to `_QUESTIONISH_LOOKUP_SIGNALS` so the guard passes even when a false positive from `_WRITE_SIGNALS` (e.g., "update" somewhere in a compound task) would otherwise block the search branch. This second edit is a one-line append in the same file; keeping it in scope as part of a single classify_rule fix.

**Generalizability:** `MEDIUM-HIGH`
- The benchmark contains several finance/quantity lookups: "how much did X cost", "how much do I owe Y", "how much time left on Z", "how long until W". Rough estimate from t-cache: 3–6 of 104 tasks use `how much` or `how long` phrasing for read-only factual lookups. None of these should be classified as `crud`. Expected to lift not just t005 but the cluster of currently-misclassified quantity questions.
- Downside risk: a task like "how much should I update the price to" contains `update` (a `_WRITE_SIGNALS` match) and `how much`. The `is_questionish_lookup` guard + `not has_write` disjunction correctly handles both branches — if the task has a write verb AND is a questionish lookup, it still routes to search. This is the intended behavior (questionish lookups are read-first, act-after).

**Zone:** `GREEN` — isolated regex change in `classify.py`, no Python logic change, no prompt change, no effect on security-related classification (`_compute_threat_level` is unaffected; `security_test` routing runs before the signal battery).

**Expected impact:** +1 on t005 (`OUTCOME_NONE_CLARIFICATION` → `OUTCOME_OK` with the correct Müller amount once the agent actually walks `50_finance/purchases/` and finds the 2026-01-31 record). Potentially +1 to +3 on other `how much / how long` tasks that are currently fallthrough-to-crud. Honest conservative estimate: **+1 to +2 tasks**.

**Risks:** Minimal. The added regex terms are disjoint from write/delete/communication/inbox signals. The `_SEARCH_SIGNALS` expansion cannot cause a task currently classified as `search` to move out of `search` (it only adds routes in). The only scenario where behavior changes for a non-t005 task is: a task that currently falls through to `crud` but begins with "how much/long/old" — and for those, `search` is the correct class anyway. No security path touched.
