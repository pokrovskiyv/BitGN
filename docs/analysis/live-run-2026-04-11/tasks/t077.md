## Failure category

**Selected:** `classification_mismatch`

**Justification:** The verifier explicitly identifies incomplete search as the blocker ("the agent's search was incomplete"), and the step budget is the direct cause of that incompleteness — 11 tool calls on a 15-step budget with a late pivot to the correct directory (step 13). If the task had classified as `search`, the budget would have been **24 steps** (per `_STRATEGY_TABLE["search"] = (24, "standard", True)`) instead of 15, and the agent would have loaded `search.md` with its LOOKUP DISCIPLINE + ANSWER PRECISION rules. The same agent, same LLM, same trajectory style would have had ~9 more steps — more than enough to reach step 13's pivot, read all Novak-family channel messages, and quote the correct one. Runner-up category: `budget_exhausted`, but that's a symptom — the *cause* is classification_mismatch picking the wrong budget and wrong fragment.

## Root cause hypothesis

**Exactly one hypothesis:**

`_SEARCH_SIGNALS` in `pac1-py/classify.py` (lines 41–45) does not include the verb `quote` or the phrase `recorded message`, and `_LOOKUP_SIGNALS` (lines 46–50) does not include `message from` / `last message`. The imperative "Quote me …" is a stylistic variant of "Tell me …" / "Show me …" / "What is …" — it is unambiguously a read-only factual lookup, but the regex misses it entirely, so the classifier falls through to `crud` (default) and the agent gets a 15-step CRUD budget with the CRUD fragment loaded.

**Evidence chain:**
1. Local repro: `classify_task("Quote me the last recorded message from Novak Oskar. Return only the exact message text.", [])` → `task_type='crud'`, `estimated_steps=10`, `target_hints=()`, `requires_write=False`. **Confirmed misclassification.**
2. Strategy table at `pac1-py/strategy.py:47–56` maps `crud → (15, standard, True)` and `search → (24, standard, True)`. The 9-step delta is the difference between budget-truncation and completion on this trajectory.
3. Fragment loading at `strategy.py:83–90` keys off `classification.task_type`, so `search.md` never loaded. The three empty `search("")` calls (steps 3–5) directly violate a rule the agent was never shown.
4. `target_hints` extractor `_PATH_HINTS` at `classify.py:124–129` matches directories like `outbox|inbox|contacts|calendar`. The instruction contains the word "message" but no directory keyword, so hints are empty and the dynamic prompt's `target_section` (`strategy.py:123–126`) was blank — the agent had no soft nudge toward `60_outbox/channels/`, which is where records of messages live.
5. Root, not symptom: fixing `outcomes.md` or adding an ANSWER PRECISION reminder would not help a task that never sees `search.md` and has a too-small budget. The only robust fix is to make the classifier recognize quote/message-retrieval imperatives as `search`.

## Fix proposal (narrow GREEN zone only)

**Selected fix class:** `classify_rule`

**Target file:** `pac1-py/classify.py`

**Exact change:**
```diff
 _SEARCH_SIGNALS = re.compile(
     r"\b(find|search|locate|look\s+for|where\s+is|which\s+files?|what(?:'s|\s+is)|"
-    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me)\b",
+    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me|"
+    r"quote(?:\s+me)?|show\s+me|tell\s+me|give\s+me|"
+    r"(?:last|latest|most\s+recent)\s+(?:message|note|entry|record))\b",
     re.IGNORECASE,
 )
```

And — because the task mentions "message" and the canonical directory is `60_outbox/channels/` — extend `_PATH_HINTS` (classify.py:124) so messages route correctly:

```diff
 _PATH_HINTS = re.compile(
     r"(?:(?:\b\w+/)+\w+(?:\.\w+)?)"  # path/to/file or path/to/dir
     r"|(?:\b\w+\.(?:md|json|txt|yaml))"  # file.ext
-    r"|(?:outbox|inbox|contacts|calendar)",  # known directories
+    r"|(?:outbox|inbox|contacts|calendar|channels|messages|threads)",  # known directories
     re.IGNORECASE,
 )
```

But per the GREEN-zone constraint (prompt_fragment / classify_rule / strategy_budget only, single fix), **the primary fix is the `_SEARCH_SIGNALS` addition**. The `_PATH_HINTS` tweak is listed as a complementary AMBER follow-up — high confidence but stretches a single fix into two hunks.

**Rationale:** "Quote me …", "Show me …", "Tell me …", "Give me …" are stylistic variants of `what/where/which/who` interrogatives. Any reasonable human classifier would route all of them to the same bucket. Adding them to `_SEARCH_SIGNALS` is a conservative widening: it only affects tasks that otherwise fell through to `crud`, and it increases the step budget from 15 → 24 while loading `search.md`'s LOOKUP DISCIPLINE rules (which would have suppressed all three empty `search("")` calls on steps 3–5). `(?:last|latest|most recent) (?:message|note|entry|record)` specifically catches the "last recorded message" pattern that defines t077.

**Generalizability:** **MEDIUM** — the broader pattern (imperative "quote/show/tell me" for a factual file lookup) plausibly recurs across 2–4 tasks in the 104-task benchmark. Every natural-language factual-retrieval task that begins with an imperative verb rather than a question word is a candidate. I can't claim HIGH without scanning all 104 instructions; I can confidently claim at least t077 benefits, and 1–2 additional tasks where the author used imperative phrasing are likely.

**Zone:** `GREEN` — pure regex addition in `classify.py`. No change to strategy, security, or defense code. Widens routing into `search`, a permissive bucket whose fragment and budget are both more appropriate for read-only lookups.

**Expected impact:** +1 on t077 (from `CLARIFICATION` at step-15-exhaustion to `OK` with the correct quoted message, because with a 24-step budget the agent would have reached step 13's pivot to `60_outbox/channels/` and still had 11 steps left to read the relevant Novak-family channel files). Potentially +1 to +2 on similar imperative-lookup tasks elsewhere. Honest conservative estimate: **+1 to +2 tasks**.

**Risks:** Low. `quote` and `show me` do not appear in any task that should classify as `crud` or `security_test` — they are unambiguously read-side. The only theoretical regression is a task like "Show me the error by writing …", but that would also match `_WRITE_SIGNALS` and take the search → crud fallback path, which is already handled by the `is_questionish_lookup` branch at line 214. Regex-level conservative.
