**Selected:** `classification_mismatch`

**Justification:** The task is a pure read-only lookup ("Quote me the last recorded message from X. Return only the exact message text") but classify.py routes it to `crud` because "Quote me" does not match any `_SEARCH_SIGNALS` token. The downstream consequences compound: (a) the agent loads `crud.md` (which has no LOOKUP DISCIPLINE, no ANSWER PRECISION, no DATE lookup rules), (b) it gets a 15-step budget instead of 24, and (c) it gets the wrong "this is a write/verify task" framing. In blind mode the score=0 is not directly conclusive, but budget exhaustion (15/15) is visible, and the verifier's independent CLARIFICATION approval is weak evidence that the answer may genuinely be absent — however, the agent lacked the canonical-folder discipline to be confident of that. Even if the correct outcome really is CLARIFICATION, the agent should have reached it in 6–8 steps with search strategy, not 15 with crud strategy.

## Root cause hypothesis

**Exactly one hypothesis:**

`_SEARCH_SIGNALS` in `classify.py` is missing quotation/extraction verbs. The pattern at lines 41–45 covers interrogative forms (`what is / which / who is / when is`) and discovery verbs (`find / search / locate / look for / where is`) but not imperative retrieval forms like `quote / show / give / tell / return / list` (when "list" is a verb with a direct object, not an analysis keyword). Tasks phrased as "Quote me X", "Show me X", "Give me the last Y", "Tell me Z" — all pure lookups — fall through to the `crud` default and get the wrong fragment + a smaller step budget.

**Evidence chain:**
1. Task instruction starts with "Quote me the…". The first word is the verb. None of the existing signal regexes inspect that verb slot for retrieval imperatives.
2. Classification output (inferred from strategy loaded): task_type = `crud` with budget 15, which matches metrics.step_count = 15 (exhausted).
3. The crud fragment (`crud.md`, 6 lines) contains only write/re-read guidance. It has no "identify canonical directory first" rule, no "include consulted files in grounding_refs", no empty-pattern search ban. The agent's step 5 `search("")` is a direct consequence of that gap.
4. Root, not symptom: tweaking outcomes.md would only polish the final-step decision; the agent's entire search trajectory was shaped by having the wrong fragment. Only fixing the classification rule moves the task onto the correct strategy track.

## Fix proposal (narrow GREEN zone only)

**Selected fix class:** `classify_rule`

**Target file:** `pac1-py/classify.py`

**Exact change:**
```diff
 _SEARCH_SIGNALS = re.compile(
     r"\b(find|search|locate|look\s+for|where\s+is|which\s+files?|what(?:'s|\s+is)|"
-    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me)\b",
+    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me|"
+    r"quote(?:\s+me)?|show\s+me|give\s+me|tell\s+me|return\s+(?:only\s+)?the)\b",
     re.IGNORECASE,
 )
```

**Rationale:** Adds imperative retrieval verbs (`quote`, `show me`, `give me`, `tell me`, `return the`) to `_SEARCH_SIGNALS`. These are all pure read-only lookups that deserve the search strategy (24-step budget, `search.md` with LOOKUP DISCIPLINE / ANSWER PRECISION, "identify canonical directory first" guidance). The new tokens are narrow enough not to collide with CRUD — "show me" is never used for create/update operations in benchmark phrasing. `return the` is anchored with optional `only` to catch the dominant "Return only the exact X" pattern used in this task and several sibling tasks.

**Why not prompt_fragment?** Adding LOOKUP DISCIPLINE to `crud.md` would fix t027 but pollute the CRUD path with read-only reasoning it doesn't need for actual create/update tasks. The classification fix is the minimal-surface intervention. Also: leaving the task on the crud track keeps it capped at 15 steps — the budget itself was a contributing factor.

**Why not strategy_budget?** Bumping the crud budget would mask the misclassification without fixing the underlying fragment mismatch.

**Generalizability:** `MEDIUM–HIGH`
- "Quote me", "Show me", "Give me", "Tell me", and "Return only the" are recurring phrasings in the BitGN benchmark. Rough estimate: 3–6 of 104 tasks are likely affected. The fix is a pure signal widening, so the blast radius is bounded — any false-positive promotion from crud to search only affects budget (+9 steps) and fragment (adds lookup discipline, adds answer precision), both of which are harmless or beneficial for read-only tasks. The only plausible regression is a task that legitimately uses "show me" as an action verb (e.g., "show me [in the UI]" — not applicable to a filesystem agent).

**Zone:** `GREEN` — small regex edit in classify.py, pure additive signal expansion, no effect on threat detection, security path, or outcome logic. No Python structural change.

**Expected impact:** Honest conservative estimate: **+1 to +3 tasks**. t027 itself gains +9 steps of budget and the correct fragment — in a non-blind follow-up run the agent would read AGENTS.MD early, consult the canonical message-log directory, and either find the answer or reach CLARIFICATION in ~7 steps instead of 15. Sibling "Quote me / Show me / Give me / Tell me / Return only the" tasks inherit the same improvement.

**Risks:** Very low. The only pathway to regression is a task where "quote me" means "cite a regulation" (not a lookup) — unlikely in this domain. No effect on security or write paths.
