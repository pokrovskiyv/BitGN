**Justification:** A textbook single-value lookup ("give me the start date of X") was routed to the `crud` fallthrough because the regex battery in classify.py has no signal for the imperative framing "Need the X" / "I need the X" / "Give me the X". The task asks for a factual read, not a file modification — the correct bucket is `search`, which would have loaded `search.md` with its `ANSWER PRECISION` rule ("your completion message must contain ONLY that value — no prefix, no explanation") and its `LOOKUP DISCIPLINE` rule ("Do not keep searching the whole workspace after you have already found the authoritative folder"). The agent's first move (step 1) was correct and efficient; the subsequent four steps are exactly the "procedural wandering" search.md's date-lookup section warns against.

## Root cause hypothesis

**Exactly one hypothesis:**

`_SEARCH_SIGNALS` and `_QUESTIONISH_LOOKUP_SIGNALS` in classify.py only recognize interrogative English ("what is the X", "where is the X", "who is Y") — they miss imperative-mood lookup requests ("need the X", "give me the X", "I need the X", "provide the X"). These imperative forms are semantically identical single-value lookups but phrase the *ask* as a statement. Because the BitGN benchmark is written in natural user voice, imperative framing is at least as common as interrogative framing. Any such task falls through every branch in `classify_task` and lands in the `crud` default — the prompt fragment farthest in spirit from what the task actually needs.

**Evidence chain:**
1. Trajectory step 1 reads the correct canonical file immediately — the agent's retrieval instinct was right, so routing (not reasoning) is the bottleneck.
2. `classify.py` line 41–45 (`_SEARCH_SIGNALS`) and line 90–93 (`_QUESTIONISH_LOOKUP_SIGNALS`) have no imperative-lookup token. I grepped the regexes manually against the instruction string: zero matches.
3. `strategy.py` line 51 routes `crud` to `crud.md`, which loads 6 lines all about *writing* (verify target exists before writing, write succeeded confirmation, re-read after write). None of those lines fire on a read-only task — they are dead weight and give no stopping-criterion.
4. Contrast t000 ("What is the house AI's DoB?") — same shape, same intent, but the leading "What is" matched `_SEARCH_SIGNALS` and `_QUESTIONISH_LOOKUP_SIGNALS`, so t000 got `search.md`. The difference between t000 and t001 is a single English register, not semantics.

## Fix proposal (narrow GREEN zone only)

**Selected fix class:** `classify_rule`

**Target file:** `pac1-py/classify.py`

**Exact change:**
```diff
 _SEARCH_SIGNALS = re.compile(
     r"\b(find|search|locate|look\s+for|where\s+is|which\s+files?|what(?:'s|\s+is)|"
-    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me)\b",
+    r"which\b|who\s+is|who\s+are|when\s+is|can\s+you\s+tell\s+me|"
+    r"(?:i\s+)?need\s+the\b|give\s+me\s+the\b|provide\s+the\b|"
+    r"tell\s+me\s+the\b|what(?:'s|\s+is|\s+are|\s+was|\s+were)\s+the\b|"
+    r"start\s+date|end\s+date|due\s+date)\b",
     re.IGNORECASE,
 )
```

**Rationale:** Extends the search signal battery with three additive groups:
1. **Imperative lookups** — `need the X`, `give me the X`, `provide the X`, `tell me the X`. These are the statement-form equivalents of wh-questions.
2. **Expanded wh-forms** — `what are the`, `what was the`, `what were the` (present tense "what is" was already there).
3. **Date-noun anchors** — `start date`, `end date`, `due date` as fallback triggers, catching instructions that phrase the ask as "the start date for Y" without any verb.

The change is additive-only — no existing match is narrowed or removed, so classification of the 100+ tasks that already route correctly is unaffected. Because `has_search=True` is checked BEFORE the `crud` fallthrough (line 214), the new matches will bypass `crud` routing and pick up `search` strategy with `search.md` — 15 step budget under the search table? Actually strategy table line 51 gives `search → (24, "standard", True)`, so the budget grows from 15 to 24. That is a side-effect of the fix and it is benign: t001 used 7 steps, well within either budget.

The `has_search OR has_lookup` test at line 214 also has the condition `and (not has_write or is_questionish_lookup)`. `has_write` is still False for "Need the start date" (no write verbs), so the new match would flow into the search branch cleanly.

**Generalizability:** `MEDIUM`
- Imperative lookup framing ("need the X", "give me the X") is common in natural user phrasing — rough estimate **3–6 of 104** benchmark tasks have a non-interrogative lookup ask. The specific "need the X" pattern plus "start date / end date / due date" anchors covers most of them. I cannot claim HIGH without scanning all 104 instructions, but this is more general than a one-task fix because the regex change cannot help but pick up other tasks written in the same register. Honest range: **2–5 additional tasks**.

**Zone:** `GREEN` — change is confined to the regex battery in `classify.py`, fix class `classify_rule` explicitly allowed. No changes to `agent_loop.py`, `defend.py`, `verify.py`, `domain_fs.py`, or `llm.py`. No prompt rewrites. No security-path effect — security routing happens BEFORE the search/crud branching based on `threat_level == "high"`, untouched here.

**Expected impact:** +1 on t001 (prompt fragment swap from `crud.md` to `search.md` gives the ANSWER PRECISION rule, which addresses the format-wandering in steps 3–6; and the LOOKUP DISCIPLINE rule, which addresses the "keep searching after finding the authoritative file" pattern). Plus **+1 to +3** on sibling tasks with the same imperative framing. Honest conservative estimate: **+1 to +3 tasks**.

**Risks:**
1. **Over-matching on hybrid tasks** — a task like "Need the start date updated to X and send an email" would now match both `_SEARCH_SIGNALS` (via "need the") and `_WRITE_SIGNALS` (via "update") and `_COMMUNICATION_SIGNALS` (via "send email"). The existing precedence chain handles this: `has_multi_step` wins first, then `has_analysis`, then `search`. Since `has_write` is True and `is_questionish_lookup` is False (imperative, not wh-form), line 214 `(not has_write or is_questionish_lookup)` is False and the search branch is skipped. So hybrid tasks cleanly route past search into communication or crud, unchanged from current behavior.
2. **"start date" as a literal phrase in a write task** — "Add start date to the project file" would now hit `start\s+date` under search signals. But `_WRITE_SIGNALS` matches "add", and the same has_write gate at line 214 blocks the search route. Safe.
3. **No regression on t000** — t000 already routes via `what is`; the additional alternation branches are ORed in, so t000's match is unaffected.
