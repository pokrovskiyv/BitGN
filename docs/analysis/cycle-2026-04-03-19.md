## Target: Premature UNSUPPORTED at step 0-1

### Failure Pattern (6 OpenRouter runs R88+R91-R95)

Step trace analysis from run_history.json reveals a clear 0-step UNSUPPORTED pattern:

| Task | Win Rate | 0-step UNSUPPORTED | Budget-exhaustion UNSUPPORTED |
|------|----------|-------------------|-------------------------------|
| t11  | 67%      | R91 (0 steps), R95 (0 steps) | — |
| t12  | 17%      | R91 (0 steps), R95 (0 steps) | R93 (13 steps), R94 (18 steps) |
| t16  | 67%      | R92 (0 steps) | R95 (4 steps) |

The model reports UNSUPPORTED as its **very first action** (0 tool calls, no reads, no exploration). This accounts for 5 of the 7 UNSUPPORTED failures across these 3 tasks.

### Root Cause
**Classification**: EDGE_CASE — missing pre_completion_gate for premature UNSUPPORTED
**File**: `pac1-py/verify.py` line 118 (GREEN zone)
**Generalizability**: HIGH — affects ANY task where model reports UNSUPPORTED without exploring

`pre_completion_gate()` has a premature-OK gate (`if outcome == "OUTCOME_OK" and step < 2`) but NO equivalent for UNSUPPORTED. The agent has 10 filesystem tools — UNSUPPORTED at 0-1 tool calls is almost never correct. The model should at least explore the filesystem before claiming it lacks capability.

### Why this is NOT a repeat
- **Cycle 2026-04-03-12**: General UNSUPPORTED gate (fired at ANY step count, regardless of exploration). Gated UNSUPPORTED unconditionally.
- **Cycle 2026-04-03-14**: _fallback_outcome reorder (changed budget-exhaustion fallback, not pre-completion gate).
- **THIS fix**: Step-count gate (fires ONLY at 0-1 tool calls). Much narrower — only catches cases where model didn't even try. After 2+ tool calls, UNSUPPORTED passes through normally.

### Why this is NOT a prompt fix
- Infrastructure fix: adds a code gate (like the existing OK-at-step-0 gate)
- Code gates have proven effective: premature-OK gate, inbox-reads gate, security-threat gate
- Gate forces exploration via code, not persuasion

### Recommended Fix
Add premature-UNSUPPORTED gate to `pre_completion_gate()` in `verify.py`, immediately after the existing premature-OK gate:

```python
if outcome == "OUTCOME_NONE_UNSUPPORTED" and step < 2:
    return (
        f"REJECTED: UNSUPPORTED after only {step + 1} tool calls. "
        "You have full filesystem tools (tree, find, search, list, read, write, delete). "
        "Explore the filesystem before claiming a task is unsupported."
    )
```

- ~5 lines added to verify.py
- No changes to agent_loop.py (step parameter already passed)
- Existing completion_gate_count (max 2) caps the gate
- Does NOT affect tasks where model reports UNSUPPORTED after exploration (step >= 2)

### Safety
- Gate fires at most 2 times (shared completion_gate_count budget)
- Model can still report UNSUPPORTED after doing 2+ tool calls
- For genuinely unsupported tasks, 2 extra exploration steps is acceptable overhead
- Parallels the proven premature-OK gate pattern
