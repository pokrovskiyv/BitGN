## Target Failure

**Tasks**: t03, t12
**Category**: TOOL_ERROR
**Points lost**: 2.0
**Previously attempted**: Yes — retry-on-ValidationError added (commit 5bf6c59), but tasks still fail

## Observation

Both t03 and t12 fail with Pydantic ValidationError due to the LLM returning malformed JSON:
- **t03**: LLM returned the inner tool schema directly (missing outer `current_state`,
  `plan_remaining_steps_brief`, `task_completed`, `function` wrapper fields)
- **t12**: Same pattern — missing wrapper fields after a search result step

The 3-attempt retry loop (commit 5bf6c59) is present but exhausted without success.

## Root Cause

The CLI backend (`claude -p`) is **near-deterministic**: identical message history → identical
LLM output. When the LLM reaches a conversational state where it returns a malformed JSON
response, the current retry logic re-calls with the **same input**, producing the same invalid
JSON all 3 times.

There is no feedback mechanism between retries. The LLM does not know it returned bad JSON.
It has no signal to change its output format on the next attempt.

## Recommended Fix

Add a **correction hint message** to the conversation history before each retry attempt
(not on the first attempt). The hint tells the LLM explicitly that its response was invalid
and restates the required JSON format.

Location: `agent.py`, the retry loop (lines ~410-418).

```python
# Before: same messages every attempt
# After: inject correction on attempt > 0

retry_msgs = messages
if attempt > 0:
    retry_msgs = messages + [{
        "role": "user",
        "content": (
            "FORMAT CORRECTION: Your previous response was not valid JSON. "
            "You MUST respond with a single JSON object containing exactly these fields: "
            "current_state (string), plan_remaining_steps_brief (array of 1-5 strings), "
            "task_completed (boolean), function (the action object with a 'tool' field). "
            "No markdown code fences. No explanation. Only the raw JSON object."
        )
    }]
job = call_llm(strategy.system_prompt, retry_msgs, model)
```

**Risk**: VERY LOW. The correction message is only injected on retry attempts (never on the
first call). It does not alter the main conversation history. It cannot trigger false security
rejections because it contains no injection patterns.

**Expected impact**: +2 points (t03, t12). Also may reduce non-deterministic failures in tasks
that occasionally hit malformed JSON responses (t10, t17).
